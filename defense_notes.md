# Шпаргалка к защите: Трекер расходов (PHP)

Файлы указаны относительно корня проекта. Прочитайте эти места в коде перед защитой: преподаватель может попросить найти фрагмент или изменить условие.

## Типовые вопросы

**Как браузер, сервер и PHP участвуют в сценарии «добавить операцию»?**
Браузер отправляет POST на `index.php?page=add`. Встроенный веб-сервер запускает `public/index.php`, тот вызывает `route()` (`src/controllers.php`). Контроллер `handleAddPost()` проверяет CSRF, вызывает `validateTransactionInput()`, при успехе сохраняет запись через `addTransaction()` и отвечает редиректом. Браузер сам делает GET на журнал, а PHP отдаёт HTML из шаблона.

**Какие данные считаются недоверенными и где проверяются?**
Всё из `$_POST` и `$_GET`: поля формы, фильтры месяца и категории, id при удалении. Проверка: `validateTransactionInput()`, `validateLimitsInput()`, `sanitizeFilters()` (`src/validation.php`), регулярное выражение для id в `handleDelete()`.

**Почему JSON именно такой?**
Список записей, у каждой `id`, `type`, `amount`, `date`, `category`, `comment`, `created_at`. Просто читать и писать до изучения СУБД. Сумма хранится в тиынах (int), потому что float накапливает ошибки округления (0,1 + 0,2 ≠ 0,3).

**Чем отличаются нормализация, валидация и экранирование?**
Нормализация приводит ввод к виду (`normalizeText()`: убрать управляющие символы, лишние пробелы). Валидация решает, допустим ли ввод (сумма > 0, дата существует, категория из белого списка). Экранирование (`h()` = `htmlspecialchars`) делает текст безопасным при выводе в HTML и применяется в шаблонах.

**Что в cookie, что в сессии?**
Cookie хранит только идентификатор сессии (HttpOnly, SameSite=Lax; задаётся в `startSecureSession()`). В сессии на сервере: CSRF-токен и flash-сообщение.

**Какие угрозы закрывает CSRF-токен?**
Чужой сайт не может заставить браузер пользователя отправить POST (добавить или удалить операцию), потому что не знает токен. Проверка: `csrfVerify()` с `hash_equals()` (`src/security.php`).

**Зачем Post/Redirect/Get?**
После успешного POST сервер отвечает `303 Redirect` на журнал. Обновление страницы (F5) повторяет GET, а не POST, поэтому операция не дублируется (`redirect()` в `handleAddPost()`).

**Что будет с повреждённым JSON или недоступным каталогом?**
`readJsonFile()` ловит `JsonException` и бросает `StorageException` с безопасным текстом. `public/index.php` показывает страницу ошибки со статусом 500, подробности пишет в журнал (`error_log`), пути и стек не показываются.

**Как защищена запись от одновременных изменений?**
`updateJsonFile()` берёт `flock(LOCK_EX)`, читает, меняет, пишет во временный файл и подменяет оригинал через `rename()`. Читатель не увидит наполовину записанный файл.

**Где используются array_filter и array_reduce?**
`sumByType()`: `array_filter` отбирает доходы или расходы, `array_reduce` суммирует. `expensesByCategory()`: `array_reduce` группирует расходы по категориям. Также `filterTransactions()` построена на `array_filter`.

**Какие функции вынесены отдельно, какие у них типы?**
Например, `parseAmountMinor(string): ?int`, `parseDate(string): ?DateTimeImmutable`, `sumByType(array, string): int`, `limitStatus(int, ?int): array`. Везде `declare(strict_types=1)`.

**Какой тест нашёл ошибку и как вы её исправили?**
Ответьте по своему опыту. Запишите это в `test-cases.md`, раздел «Журнал найденных ошибок». Если автотест упал при вашем запуске, исправьте код и расскажите про этот случай.

**Следующий шаг после ООП и PDO?**
Заменить JSON на SQLite или MySQL через PDO, оформить сущности классами `Transaction`, `Repository`, добавить авторизацию и редактирование.

## Что могут попросить изменить (где править)

| Просьба | Где менять |
|---|---|
| Добавить категорию «Подарки» | `src/config.php`: `expenseCategories()` |
| Максимальная длина комментария 100 | `src/config.php`: `MAX_COMMENT_LENGTH` |
| Запретить даты старше 2020 года | `src/config.php`: `MIN_DATE` |
| Предупреждение с 90 % лимита вместо 80 % | `src/transactions.php`: `limitStatus()`, условие `$percent >= 80` |
| Разрешить будущие даты | `src/validation.php`: убрать ветку `$date > $today` |
| Валюта доллары вместо тенге | `src/view.php`: `formatMoney()` |
| Добавить в журнал колонку «id» | `templates/journal.php` |
| Показать только расходы | `filterTransactions()` или условие в `pageJournal()` |

## Перед защитой
1. `php tests/run.php` — все проверки PASS.
2. `php scripts/seed.php --force` и `php -S localhost:8000 -t public`.
3. Подготовьте основной сценарий (добавить расход, фильтр, сводка) и один ошибочный (сумма 0 или дата в будущем).
4. Откройте репозиторий: README, история коммитов, тег `v1.0.0`.
